# 统一 .env 配置改造 + 部署指南

## Context

当前项目前后端配置分散且硬编码：`frontend/vite.config.js` 代理写死 `http://192.168.1.7:8001`、`run.py` 默认 host 写死 `192.168.1.7`、数据库连接在 `app/config.py` 用代码默认值（`.env` 机制已有但文件不存在，且 env_file 相对 cwd 解析不可靠）。用户更换办公地点时需要逐处改 IP，易漏易错。同时 `start-backend.bat`（8003）与主流程（8001）端口不一致、`parent-portal` 代理指向遗留的 8003、README 部署内容过时（5173 端口、无 run.py/初始化说明）。

目标：
1. 根目录新建统一 `.env`，换环境只改 `SERVER_IP` 一处（监听固定 0.0.0.0、代理固定走 127.0.0.1，均不受换 IP 影响）
2. 新建《部署指南.md》：数据库创建、前后端初始化启动、后端接口介绍、前端页面功能与注意事项
3. parent-portal 纳入统一配置，代理修正到 8001（用户已确认）

## 文件清单

**新建（3）**：
- `d:\DD-CLASS-main\.env` — 实际配置（.gitignore 已忽略，不入库）
- `d:\DD-CLASS-main\.env.example` — 模板（入库，密码/密钥用占位符）
- `d:\DD-CLASS-main\部署指南.md` — 中文部署文档

**修改（5）**：
- `app/config.py` — 扩展字段 + env_file 改绝对路径
- `run.py` — argparse 默认值从 settings 读 + 打印局域网访问地址
- `start-backend.bat` — 改为 `python run.py`（修正 8003 遗留）
- `frontend/vite.config.js` — loadEnv 读根 .env，proxy 走 127.0.0.1
- `parent-portal/vite.config.js` — 同构改造，修正 8003→8001

**不动**：两个前端的 axios 封装（baseURL='/api' 走 proxy）、`app/database.py`、`app/main.py`、`.gitignore`（第 29 行已忽略 .env）、README.md。

## 实施步骤

### 1. 新建 `.env` / `.env.example`

```ini
# DD-CLASS 班级管理系统 统一配置
# 换办公地点/局域网 IP 变化时：只需修改 SERVER_IP 一处，重启服务生效

# ---------- 服务器地址（唯一需按环境修改的项）----------
SERVER_IP=192.168.1.7

# ---------- 后端服务（监听 0.0.0.0 允许局域网访问）----------
BACKEND_HOST=0.0.0.0
BACKEND_PORT=8001

# ---------- 主前端（班主任端）----------
FRONTEND_HOST=0.0.0.0
FRONTEND_PORT=3000

# ---------- 家长端前端 ----------
PARENT_HOST=0.0.0.0
PARENT_PORT=5174

# ---------- 数据库（PostgreSQL）----------
# 密码避免使用 $ 和引号
DATABASE_URL=postgresql://ddclass_user:your_password@127.0.0.1:5432/ddclass

# ---------- 安全 ----------
SECRET_KEY=your-super-secret-key-change-in-production
ACCESS_TOKEN_EXPIRE_MINUTES=1440
```

`.env` 写当前真实值（SERVER_IP=192.168.1.7、数据库连接用当前在用的）；`.env.example` 用占位符。注意：`.env` 的 DATABASE_URL 要从当前运行环境取真实值（当前 config.py 默认值即真实值时直接沿用）。

### 2. 改 `app/config.py`（全量替换）

- `BASE_DIR = Path(__file__).resolve().parent.parent`
- 新增字段：SERVER_IP、BACKEND_HOST、BACKEND_PORT、FRONTEND_HOST、FRONTEND_PORT、PARENT_HOST、PARENT_PORT（沿用现有 DATABASE_URL/SECRET_KEY/ALGORITHM/ACCESS_TOKEN_EXPIRE_MINUTES 默认值）
- `model_config = SettingsConfigDict(env_file=str(BASE_DIR / ".env"), env_file_encoding="utf-8")` — 绝对路径，与启动 cwd 无关（pydantic-settings 2.1.0 支持）
- 缺 .env 时全部回落默认值，系统仍可启动

### 3. 改 `run.py`（仅 main() + docstring）

- `--host`/`--port` 默认值改 None，实际值 `args.host or settings.BACKEND_HOST`、`args.port or settings.BACKEND_PORT`（命令行可覆盖 .env）
- 修正原 help 文案矛盾（默认 0.0.0.0 vs 实际 192.168.1.7）
- 启动前打印横幅：后端监听地址 + 基于 SERVER_IP 的三个局域网访问地址（后端 API / 班主任端 / 家长端）
- docstring 示例更新为"地址端口默认读根目录 .env"

### 4. 改 `start-backend.bat`

`python -m uvicorn app.main:app --host 0.0.0.0 --port 8003` → `python run.py`

### 5. 改 `frontend/vite.config.js`（全量替换）

```js
import { defineConfig, loadEnv } from 'vite'
// ...
const projectRoot = fileURLToPath(new URL('..', import.meta.url))

export default defineConfig(({ mode }) => {
  const env = loadEnv(mode, projectRoot, '')  // 空前缀 = 加载全部变量
  const backendPort = env.BACKEND_PORT || '8001'
  const frontendHost = env.FRONTEND_HOST || '0.0.0.0'
  const frontendPort = Number(env.FRONTEND_PORT) || 3000
  return {
    plugins: [vue()],
    resolve: { alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) } },
    server: {
      host: frontendHost,
      port: frontendPort,
      proxy: {
        '/api': { target: `http://127.0.0.1:${backendPort}`, changeOrigin: true }
      }
    }
  }
})
```

`loadEnv` 为 Vite 官方导出 API，内部用 dotenv 解析（支持 # 注释/空行/引号），零新增依赖。`import.meta.url` 相对解析在本项目现有 alias 配置中已验证可用。

### 6. 改 `parent-portal/vite.config.js`

同构，差异：`new URL('../..', import.meta.url)`；读 `PARENT_HOST`/`PARENT_PORT`（默认 0.0.0.0/5174）；proxy target 同为 `http://127.0.0.1:${env.BACKEND_PORT || '8001'}`（修正 8003）。

## 风险

- .env 不入库：交接需同步 .env.example + 指南中"复制为 .env"步骤
- dotenv `$` 插值歧义：DATABASE_URL 密码避免 $ 和引号（FAQ 覆盖）
- 改 .env 后需完全重启进程（uvicorn --reload 只监视 .py）
- 当前 8001/3000 可能有旧服务在跑，验证前先检测端口占用
