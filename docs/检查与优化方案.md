## 三、问题清单与修复方案

### 问题 1【严重·P0】家长端 6 个接口在 PostgreSQL 下全部 500，家长端口实际不可用

- **现象**：`GET /api/parent/{verify|student|scores|stats|notifications|homework}` 对任何**有效**家长码全部返回 500 `Internal Server Error`（无码/已撤销的请求因不走过期判断而正常）。
- **根因**：`app/routers/parent.py` 中家长码过期判断 `student.parent_code_expires < datetime.now()`。列类型为 `DateTime(timezone=True)`（PostgreSQL `timestamptz`），取回的是**带时区**的 datetime，与**不带时区**的 `datetime.now()` 比较抛 `TypeError: can't compare offset-naive and offset-aware datetimes`。生成家长码时必设一年有效期 → 所有有效码必然触发。
- **为何一直没发现**：从 SQLite/MySQL 迁移到 PostgreSQL 后才出现（SQLite 返回 naive datetime）；pytest 测试跑在 SQLite 上，未覆盖该场景。
- **修复**：`parent.py` 增加 `_code_expired(student)` 帮助函数——带时区时用 `datetime.now(exp.tzinfo)` 比较，不带时区用 `datetime.now()`；6 处判断统一替换。
- **回归**：pytest 新增用例——种子学生的 `parent_code_expires` 写入**带时区**的过期/未过期时间各一档，验证 verify/scores 返回正确（SQLite 下模拟 PG 行为，守护两类方言）。

### 问题 2【潜在·P1】家长端 stats 接口除零风险

- **现象**：`/api/parent/stats` 中 `sum(...)/len([...])` 的分母是「成绩非零的科目数」，若学生所有成绩为 0（或缺考 0 分），分母为 0 → `ZeroDivisionError`。当前被问题 1 掩盖。
- **修复**：分母取自同一个过滤后的列表长度，空列表时平均分记 0。

### 问题 3【体验·P2】页面访问配置变更后，已登录浏览器首次深链接被弹回仪表盘

- **现象**：管理员在「页面访问管理」改完某页可见性后，已登录的其他会话localStorage 里 `hidden_pages` 仍是旧值；该会话直开/刷新该页面时，路由守卫先于配置刷新执行，用旧值判断 → 误弹回 `/dashboard`。被弹回的这次导航会触发配置重新拉取，**第二次进入即恢复正常（自愈）**。
- **修复**：守卫仅当本地 `hidden_pages` 已初始化（登录后至少拉取过一次）时才拦截；Layout 挂载并刷新配置后，若当前页已被隐藏再主动跳转。改动小，不影响权限语义。

## 四、成绩分析功能调研与拓展方案

### 4.1 成熟产品功能对照

结合 [智慧教务云平台成绩分析](http://www.fengshicom.com/shouce/chengji.html)、[新教育班级报告](https://hc.xinjiaoyu.com/student-analysis/e776)、[好分数](https://yunxiao.com)、[智学网教师端](https://apps.apple.com/cn/app/%E6%99%BA%E5%AD%A6%E7%BD%91%E6%95%99%E5%B8%88%E7%AB%AF/id1064856546)、[班级喵进退步分析](https://www.sohu.com/a/1086054647_1210115215) 等：

| 功能 | 成熟产品 | 本系统现状 | 结论 |
|---|---|---|---|
| 平均/最高/最低/中位数/标准差 | ✓ | 仅平均/最高/最低 | **缺中位数、标准差** |
| 三率（优秀率/及格率/低分率）按科统计 | ✓ | 仅分数段饼图 | **缺** |
| 分数段分布 / 一分一段 | ✓ | 有 5 档饼图 | 已有雏形，**缺 10 分段明细** |
| 进步/退步名单（相邻考试名次变化） | ✓ | 无 | **缺（班主任最高频诉求）** |
| 临界生名单（提优/补差对象） | ✓ | 无 | **缺** |
| 科目均衡分析（雷达图，班级 vs 年级） | ✓ | 无 | **缺** |
| 学生个体报告（排名趋势/单科/薄弱科目） | ✓ | 已有 | 已具备 |
| 班级横向对比 | ✓ | 已有（班级 vs 全校均分） | 已具备 |
| 年级排名/赋分/选科走班 | ✓ | 不适用 | 不做（本系统为班级制单班主任场景） |

### 4.2 拓展设计：新增「考试报告」

以**一场考试**（沿用现有「考试类型+日期」聚合键）为中心生成班级成绩报告，前端成绩分析页改为 Tab 布局。

**后端新增 2 个端点**（`app/routers/analytics.py`）：

1. `GET /api/analytics/exams?class_id=&semester=` → 该班级该学期的考试列表（key/label/日期/参考人数），供前端考试下拉。
2. `GET /api/analytics/exam-report?class_id=&semester=&exam_key=` → 完整报告：

```
{
  "exam": {"key", "label", "exam_type", "date"},
  "summary": {                          // 按学生总分
    "student_count", "avg", "median", "max", "min", "std_dev",
    "excellent_rate", "pass_rate", "low_rate"   // 优秀≥85%总分制？→ 采用固定阈值：优秀=总分/科目数≥90、及格≥60、低分<40
  },
  "subjects": [                         // 每科一行的三率表
    {"subject_name", "avg", "max", "min", "std_dev",
     "excellent_rate", "pass_rate", "low_rate", "grade_avg"}
  ],
  "segments": [{"label": "90-100", "count"} ...],   // 总分按满分比例折算为百分制后 10 分一段
  "rankings": [                         // 全员名次表（含与上一场考试的对比）
    {"student_id", "student_name", "total_score", "rank",
     "prev_rank", "rank_change"}        // rank_change = prev_rank - rank，正数为进步
  ],
  "critical": {
    "excellence": [...],                // 总分距优秀线 ≤5 分（折算百分制）
    "pass": [...]                       // 总分距及格线 ≤5 分
  },
  "balance": {                          // 科目均衡：班级 vs 全校各科均分（百分制折算）
    "subjects": ["语文", ...],
    "class_avg": [...], "grade_avg": [...]
  }
}
```

计算口径（与系统现状对齐的约定）：
- 「考试」= 现有 `_exam_key`（考试类型+日期）；上一场 = 同学期按日期排序的前一场。
- 不同科目满分可能不同（等级科目不入成绩，计分科目默认百分制）——**折算百分制**后再算总分与分数段：总分 = 各科(百分制)之和；三率线：优秀 90、及格 60、低分 40（按平均分折算，即总分/科目数）。
- 临界生：折算平均分 ∈ [85,90) 为优秀临界、[55,60) 为及格临界。

**前端改版 `ScoreAnalysis.vue`**：

- 顶部条件：班级 + 学期 +（新增）考试下拉（考试报告 Tab 必选）。
- Tab 1「考试报告」：指标卡行（人数/平均/中位数/标准差/最高/最低 + 三率）→ 各科三率表格 → 总分分数段柱状图 → 科目均衡雷达图（班级 vs 全校）→ 进退步表格（进步标绿/退步标红，支持只看变化名单）→ 临界生两张卡片。
- Tab 2「学生分析」：现有内容原样保留（排名趋势、单科成绩、科目对比、薄弱科目）。

### 4.3 明确不做（及理由）

- 年级排名、赋分转换、选科走班：超出单班级班主任场景；
- 报告导出 PDF/Word：可后续按需加（当前有 Excel 导出兜底）；
- AI 学情诊断：无 LLM 集成规划。
